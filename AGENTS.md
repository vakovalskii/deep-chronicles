# Рабочий процесс: Godot — основной клиент

MMORPG-песочница в духе классических корейских MMO (механика своя, названия свои — никаких
имён и ассетов чужих игр). **Сервер авторитетный**: он владеет прогрессом, мобами и боем;
клиент шлёт намерения и рисует ответ, локально ничего игрового не хранится.

Документация по онтологии — `docs/gitmark/`, вход: `docs/gitmark/README.md`; искать —
`python3 .claude/skills/kb-search/gitmark.py search "<тема>"`.

С 2026-09-18 развиваем нативную игру в `godot/` (Godot **4.7.2**, GDScript, Mobile renderer; Metal на macOS). Пользователь выбрал Windows, macOS, Android и iOS. Браузерная игра закрыта по прямому решению пользователя; не поддерживать и не возобновлять её. `site/` — только скачивание нативных клиентов и онлайн. Общие `src/data.js`, `stats.js`, `sim.js`, `progression.js`, `world-core.js` нужны серверу/экспорту и не являются удаляемым легаси.

## Запуск и проверка

- `npm ci` (Node 22.23.1), затем `npm run dev` / `npm run native`: экспорт общих данных, импорт Godot, окно игры с **основным сервером** `wss://realms.neuraldeep.ru/ws`. `npm run native:local` явно запускает отдельный локальный мир. `GODOT_BIN` переопределяет путь к движку.
- `npm run native:editor`: редактор. `npm run native -- --skip-assets`: быстрый запуск после готового импорта.
- `npm run native:verify -- --build=macos`: воспроизводимый конвейер правил, сервера, UI в Godot, оружия, TLS к основному серверу и сборки; отчёт/хеши/логи в `.native-run/verification/`. Подробности: `docs/NATIVE_PIPELINE.md`. `--headless --offline` — CI без графики/продакшена; `npm run test:native -- --touch` — сенсорная раскладка.
- `npm test`: JS-правила, сервер, нативный smoke-тест с реальным рендером. `npm run test:native -- --headless` годится для CI, но не заменяет визуальную проверку.
- `npm run native:build -- macos` / `windows` / `android --debug` / `ios`: экспорт соответствующего preset. Для мобильных целей нужны SDK и подпись; наличие preset не означает проверку на устройстве.
- `npm run native -- --built --skip-assets`: проверка собранного macOS-приложения.
- `npm run native:verify -- --release`: правила + сервер + Godot + оружие + расчёт экономики + обе настольные сборки + сайт скачивания/статуса. `--web` больше не поддерживается; старые `src/main.js`, `index.html`, `tests/e2e.mjs` оставлены как архив. Не тратить работу на совместимость браузерной игры. `npm run native:economy` пишет расчёт в `.native-run/`.
- После визуальных изменений запустите игру, проверьте скриншот и оставьте пользователю открытое окно. Убедитесь, что в `.native-run/client.log` нет ошибок. Не подменяйте запуск сообщением с инструкцией.

## Источники истины

- `server/` и общие `src/data.js`, `src/stats.js`, `src/sim.js`, `src/pvp.js`, `src/world-core.js` сохраняют правила, протокол и авторитет сервера. Не переносите расчёт наград, урона, покупок или прогресс в клиент.
- `tools/godot/export.mjs` экспортирует каталоги, высоты, препятствия, размещение моделей и резервные анимации. `godot/generated/` пересоздаётся и не коммитится; не редактируйте его вручную.
- `tools/godot/placements.mjs` заменяет только внешний вид исходных форм. Серверные препятствия, NPC, спавны и координаты остаются общими.
- Редактируемая графика: `godot/assets/`, реестр `godot/assets/manifest.json`, свет `godot/scenes/world.tscn` + `godot/resources/daylight.tres`, шейдеры `godot/shaders/`.
- Интерфейс: `godot/scripts/hud.gd`, `chat_panel.gd`, `window_frame.gd`, `character_preview.gd`, `item_slot.gd`, `map.gd`, `joystick.gd`. Проверяйте здоровье/ману/опыт, цель, мини-карту, чат, навыки, сумку, 12 слотов экипировки, заточку, магазин, телепорты, жреца и смерть. Не скрывайте UI ради красивого кадра.

## Визуальное направление и публикация

- Пользователь дал референсы классической L2: строгие компактные панели, прямые тонкие рамки, HP/MP/EXP слева сверху, явная цель по центру, сумка справа, чат слева снизу и десять ячеек снизу. Не возвращать большие скруглённые карточки. Подробности: `docs/UI_STYLE.md`.
- Цель обязана явно выделяться кольцом, стрелкой, именем и HP; smoke проверяет реальный экранный клик по мобу. Окна перетаскиваются; в персонаже и при создании есть 3D-предпросмотр.
- Сайт `site/` раздаёт ZIP Windows/macOS и показывает реальный онлайн из приветствия WS. Сборка — `site:build`, проверка — `test:site`, полная публикация — проверенный релиз. `docs/DISTRIBUTION.md` описывает процесс и ограничения подписи; обновлятора нет.

## Меню, сервер и воспроизводимость

- Обычный запуск и экспортированное приложение подключаются к основному серверу; случайный quick-start допустим только для явно выбранного локального режима. Не создавайте тестовые аккаунты в продакшене.
- Персонажи/вещи/прогресс читаются из серверного `authok` / `you` / `snap`. Локальную БД не загружать на основной сервер. Godot использует прежние серверные аккаунты. Поддержка браузерной игры прекращена.
- Токены разделены по endpoint (`user://sessions.json`), чат/миникарта/панель — `interface.cfg` через `interface_settings.gd` с объединением секций. Тестовый режим не читает и не перезаписывает пользовательские файлы.
- Системный журнал находится НАД чатом в отдельной панели с собственными историей и прокруткой. Фильтры бой/награды/уведомления, размер/высота и граница сохраняются. Ввод над UI не управляет камерой (проверяется настоящими событиями мыши). Миникарта: +/− и колесо, пределы 0.5–8 м/пиксель.
- Панель: десять назначаемых ячеек, цифры повторяют назначение; разблокировка разрешает обмен ячеек перетаскиванием. Постоянные кнопки атаки/подбора/цели и автолут остаются доступны. Настройки отдельны по классу.
- Восстановлены: продажа стопок, полные характеристики/атрибуты/комплекты, умения, меню/управление/настройки, чат Все/Торг/Рядом/ЛС, баффы, опыт, цель, счётчик онлайн. Не заменять их заглушками.
- Метки мобов/игроков на обеих картах — только из живых снимков, без мёртвых/устаревших. Полная карта показывает отдельную область катакомб.
- Оружие: `DEF-hand.R` → `WeaponGrip` с центром рукояти в ладони; +Z клинка совпадает с +Z кости. Размер компенсирует масштаб модели, щит крепится к левому предплечью. `npm run native:weapons` проверяет шесть поз и пишет скриншот. Смена меча/посоха должна менять реальную модель, в том числе у мага.
- Все изменения оставлять воспроизводимыми через код/сценарии/зафиксированные ассеты и документировать в `docs/NATIVE_PIPELINE.md`. Скриншоты окон: `.native-run/test-artifacts/`, сенсорных — `.native-run/test-touch-artifacts/`.

## Модели и текстуры

- Пользователь явно требует нормальные текстурированные формы. Примитивы — только резервный вариант, а не готовые герои, мобы или дома.
- Концепты хранятся в `art/concepts/`, сведения об источниках — `art/README.md`. Оригиналы TRELLIS лежат в игнорируемом `tools/models-out/`, подготовленные GLB — в `godot/assets/` и в git.
- `npm run native:art -- <id>`: Blender подготавливает выбранную модель из `tools/models-out/`; `BLENDER_BIN` задаёт путь. `rig.py` переносит веса в совпадающей A-позе и возвращает меш в каноническую T-позу. `rig-creature.py` создаёт скелеты и клипы животных/членистоногих. `prepare-static.py` ограничивает полигоны для повторяющейся растительности.
- Не пересчитывайте вслепую нормали неманифолдной TRELLIS-геометрии: это разворачивает отдельные оболочки и создаёт дыры. Сохраняйте UV и проверяйте персонажей в движении.
- Кэш PackedScene в `art_assets.gd` удерживает общие материалы; без него при удалении сетевых акторов возникали ошибки renderer `material is null`.
- Земля использует отдельные рисованные albedo, mipmaps и анизотропную фильтрацию. Не отключайте mipmaps: иначе поверхность рябит при движении камеры.
- `npm run native:gallery -- --models=warrior,mage,wolf --output=/tmp/gallery.png`: реальный рендер ассетов для проверки.

## Данные и внешние системы

- Локальный запуск использует `.native-run/world.db`, не базу продакшена. Native-тест создаёт отдельную временную БД и включает `DEV_CMD` только для неё. Не запускайте обычную игру с `DEV_CMD=1`.
- `.env`, SSH-адреса, токены, БД, `godot/export_credentials.cfg`, `.godot/`, сборки и логи не коммитятся. Не печатайте значения секретов.
- Генерация обращается к TRELLIS через SSH-туннель; настройка 512 подходит для серии моделей на GPU 24 ГБ, 1024_cascade задаётся явно. Не останавливайте посторонние GPU-задачи.
- Выкладка сайта/сервера и синхронизация публичного репозитория — отдельные действия. Обычный запрос на локальные изменения/коммит их не подразумевает.
- Сохраняйте чужие незакоммиченные изменения. При начале этой миграции `tools/trellis/texture.py` уже был изменён пользователем; он не входит в миграцию.

## Релиз

- `npm run native:verify -- --release`, затем `npm run deploy -- --verified`. Проверяются хеши всех входов/результатов, сайт и обе сборки. `npm run deploy` сам запускает полный конвейер.
- `deploy/release.mjs` загружает staging, `promote.sh` сохраняет предыдущий код и SQLite на сервере, обновляет код/статику и службу. БД с компьютера никогда не загружается. Внешний TLS probe проверяет `progression:1` / `nativeOnly:1`. Адрес подключения берётся из `.env` и не печатается.
- Публичная статика — страница скачивания `site/`, не браузерная игра. EXE с встроенными ресурсами автоматически упаковывается в `godot/builds/windows/khroniki-glubin-windows.zip`; оба ZIP и SHA-256 входят в `dist/release.json`.
- Старый `deploy/quick.sh` теперь завершается с ошибкой и не может вернуть браузерную игру. Единственный путь — проверенный native-релиз.

## Кто что считает — серверные правила
Правило простое: **всё, что влияет на прогресс, считает сервер**. Клиент отвечает за камеру,
ввод, эффекты и предсказание собственной ходьбы.

| На сервере | На клиенте |
|---|---|
| профиль, сумка, экипировка, заточка, монеты, опыт, уровень | отрисовка, частицы, подписи, звук интерфейса |
| мобы: спавн, ИИ, агро, урон, смерть, дроп, респавн | интерполяция мобов и игроков по снапшотам |
| весь бой: автоатака, умения, PvP, стражи, карма | шаг к цели, чтобы попасть в радиус (положение шлёт `st`) |
| переходы в катакомбы, телепорты, возрождение | полоса каста, окна, перетаскивание в инвентаре |

Положение по-прежнему ведёт клиент (иначе ходьба станет ватной), но сервер проверяет скорость
и при рывке отвечает `fix` — клиента возвращает назад.

Godot правила **не дублирует**: `tools/godot/export.mjs` импортирует общие JS-модули в Node и
запекает `godot/generated/` (мир, каталог, высоты, модели, `UI_RULES`, фикстуры статов).
`godot/generated/` пересоздаётся и не коммитится — руками не править.

## Структура
Общее (сервер + клиенты + экспорт в Godot):
- `src/data.js` — классы (атрибуты СИЛ/ЛОВ/ВЫН/ИНТ/МДР/ДУХ), умения, `SLOTS` (12 слотов куклы), предметы (грейды, вес `w`, `set`, `twoHand`, `robe`, `full`), `SETS`, мобы, магазин, опыт. Без импортов.
- `src/stats.js` — без DOM: `calcStats` (атрибуты, экипировка, заточка `enchValue`, комплекты, перегруз), `equipFromBag`/`unequipSlot`, `wearError`, `migrate`. Покрыт юнит-тестами.
- `src/sim.js` — общие правила без three.js: `calcDmg`, `missChance`/`evaChance`, `xpForKill`, `rollDrops`, ИИ моба `mobStep`, `moveEntity` (с сеткой препятствий), цены и заточка. Случайность приходит аргументом `rng` — поэтому проверяется юнит-тестами детерминированно.
- `src/world-core.js` — **ядро мира без рендера**: рельеф (`heightAt`), зоны (`zoneAt`), расстановка построек, препятствия-круги `obstacles`, лабиринт катакомб (отдельная площадка x ≥ 2200, пол y = 0), `TELEPORTS`, `buildProps(B)` → NPC и точки спавна. Формы отдаёт через эмиттер `B`; сервер передаёт `nullEmitter` и получает только данные.
- `src/pvp.js` — константы PvP: флаг, карма, стражи, дроп с PK.

Сервер:
- `server/server.js` — WS и главный цикл 10 Гц: приём команд, бой, PvP, стражи, снапшоты (игроки + мобы, радиус 220 м), чат.
- `server/sim/player.js` — профиль на сервере: сумка, экипировка, магазин, заточка, телепорты, опыт, смерть. `SAVE_VERSION=3` не повышать ради новых полей: SP/навыки/автолут мигрируют без сброса старых персонажей через `src/progression.js`.
- `server/sim/mobs.js` — экземпляры мобов из `buildProps()`, тик ИИ, урон, смерть и награда тому, кто нанёс больше урона.
- `server/accounts.js` — SQLite: пароли scrypt + соль, токены sha256. Профиль пишет только сервер; от клиента при регистрации берётся лишь класс.

Нативный клиент (`godot/`):
- `scenes/main.tscn` → `scripts/main.gd` — сборка сцены кодом, разбор сообщений сервера, ввод, камера, цель, эффекты; печатает `NATIVE_READY`.
- `scripts/network.gd` — WebSocket-автозагрузка: соединение, переподключение, токены по адресу сервера (`user://sessions.json`).
- `scripts/data.gd` — автозагрузка: читает `generated/*`, высота рельефа, сетка препятствий; зеркало правил статов **только для предпросмотра**, считает всё равно сервер.
- `scripts/hud.gd` + `chat_panel.gd`, `window_frame.gd`, `character_preview.gd`, `item_slot.gd`, `map.gd`, `joystick.gd` — весь интерфейс.
- `scripts/world.gd`, `actor.gd`, `art_assets.gd` — мир, сущности, реестр моделей по `godot/assets/manifest.json`.
- Графика: `godot/assets/` (коммитится), свет `godot/scenes/world.tscn` + `godot/resources/daylight.tres`, шейдеры `godot/shaders/`, концепты `art/concepts/`.

Браузерный клиент (легаси): `src/main.js`, `src/world.js`, `src/tex.js`, `src/skin.js`.
`src/models.js`/`src/glb.js` теперь нужны в основном экспорту моделей в Godot.

## Протокол
- Клиент → сервер: `auth`/`login`/`register`, `st`, `atk {id, kind, hold}` (`hold` — только взять на прицел), `skill`, `use`, `equip`/`unequip`, `buy`/`sell`, `ench`, `tp`, `respawn`, `wash`, `chat`/`pm`.
- Сервер → клиент: `authok`/`you` (профиль целиком — так не бывает рассинхрона), `snap` (игроки `o`, мобы `m`, своё `me`), `mobs` (вид впервые увиденного моба), `ev` (события боя для отрисовки), `fix`, `look`, `me`, `announce`, `chat`/`pm`.
- Внешний вид собирает сервер из экипировки (`lookOf` в `server/server.js`); добавил новый вид — добавь поле там.
- Отладочная команда `dev` (телепорт, монеты, вещи, уровень) работает **только** при `DEV_CMD=1` — его ставят автотесты, в проде его нет. Обычную игру с `DEV_CMD=1` не запускать. Лимит попыток входа поднимается `AUTH_TRIES`.
- Godot использует старые аккаунты; браузерный UI больше не поддерживается. Полный справочник кадров —
  `docs/gitmark/reference/protocol.md`. Тестовый хук `window.__g` — только в браузере, в dev или с `?test`.

## Принципы
- Интерфейс и комментарии — на русском.
- Клиент видит мир на ~250 мс в прошлом (снапшот + интерполяция), поэтому сервер даёт допуск `LAG_M` на дистанцию удара по движущейся цели.
- Подписи — до 20 ближайших мобов.
- Точки телепорта и возрождения не должны попадать в препятствия (проверяется тестом).
- Расстановка мира детерминирована: меняя `world-core.js`, сверяйся с юнит-тестами про спавны и проходимость лабиринта.
- UI-ориентир — классическая L2: компактные прямые рамки, HP/MP/EXP слева сверху, явная цель по центру, сумка справа, чат слева снизу, десять ячеек снизу. Без больших скруглённых карточек. См. `docs/UI_STYLE.md`.
- Локальные сохранения в продакшен не переносятся: токены разделены по адресу сервера, для основного персонажа нужен вход в тот же аккаунт. Тестовых аккаунтов в проде не создавать.
- Сохраняйте чужие незакоммиченные изменения (`tools/trellis/texture.py` менялся пользователем и к переезду на Godot не относится).

## Смерть, дроп и инвентарь

- По новому запросу пользователя автолут восстановлен и включён по умолчанию. Сервер выдаёт награду победителю через `creditLoot` с немедленным сохранением; при ошибке сохраняет её как наземный дроп. При выключенном автолуте монеты/вещи только по `pickup`. Опыт и SP за убийство начисляются независимо. Правила: `docs/GROUND_LOOT.md`, `src/loot.js`, `src/progression.js`. Это заменяет прежнее требование «только ручной подбор».
- Подбор проверяет расстояние, жизнь, владельца и повтор; профиль сохраняется сразу. Неподнятые объекты исчезают при рестарте процесса. Проверять связку двух клиентов и реальный клик/подход.
- Инвентарь: постоянная строка монет и веса, поиск, фильтры и сортировка; команды всегда используют исходный серверный индекс. Рисовать модели смерти, подписи и реальные объекты добычи.
- Дополнительное исследование C4: `docs/C4_RESEARCH.md`; `npm run native:references` воспроизводит набор изображений с проверкой хешей. Смешанный архив C4/C5 не считать достоверным C4 для всех деталей.

## Прогрессия и рельеф

- `skills: {id: rank}`, `sp`, `autoloot` сохраняет сервер. Новый герой получает только базовый навык; старый v3-профиль сохраняет ранее доступные умения первого ранга. Новые ранги покупаются кнопкой в K за SP при достаточном уровне. Команда `learn {id,rank}` защищена ожидаемым рангом. Событие `buff` несёт реальный множитель сервера.
- У обеих специализаций есть B-оружие/комплект; `RECIPES` и `cmdCraft` дают гарантированный путь через ресурсы/печати. Крафт только возле торговца, сохранение сразу, откат при сбое. Иконки новых B-предметов используют семейства существующих иконок; уникальные новые 3D-модели для каждого предмета в этой итерации не создавались.
- Бесплатные стартовые вещи и печати нельзя продавать; не возвращать `price || 4000` в `sellPrice`. Экономические расчёты и тесты проверяют отсутствие выгодного цикла крафт→NPC.
- Рендер рельефа теперь использует сетку 4 м и ту же диагональ треугольников, что `presentationHeightAt`. Декорации привязаны к этой поверхности; крупные камни заглублены по опорным точкам. Не возвращать сетку 10 м: она давала зазоры до 0.85 м. Серверные коллизии/спавны неизменны.

## Проверки связи, чата и перетаскивания

- `network.gd` пишет ограниченный по размеру `user://network.jsonl`: событие, платформа, код и причина разрыва; без токенов/паролей/переписки. Настройки → «Открыть сетевой журнал». На Windows: `%APPDATA%/Godot/app_userdata/Хроники Глубин/network.jsonl`.
- При возвращении фокуса сначала poll существующего сокета; не рвать живую связь по старой отметке времени. JSON ping/pong работает и до входа; heartbeat feature = 1. Закрывающееся соединение имеет таймаут; ошибки отправки обрабатываются. Сигнал сообщения может заменить сокет — старый цикл обязан остановиться.
- Чат того же персонажа сохраняется после переподключения. При отсутствии связи черновик не стирается. Проверяются мир/торг/рядом/ЛС, дальность, cooldown, /w, /r, кавычка перед именем, фильтры, история, прокрутка и отсутствие воздействия на камеру.
- «Замок» над панелью переключает редактирование. В режиме редактирования клик не применяет навыки; доступны перетаскивание иконок изученных навыков из K, обмен ячеек, включая пустые и перезарядку. Тест использует настоящие press/motion/release, а не прямой swap_slots.
- `native:bootstrap` скачивает Godot 4.7.2 и настольные templates с проверкой закреплённых SHA-512. `.github/workflows/native.yml` проверяет Windows/macOS, затем собранное приложение (`test:native -- --headless --built`) и 65 секунд TLS (`native:probe -- --built --seconds=65`). CI не входит в аккаунты продакшена.
- `release-contract.mjs` проверяет не только хеши, но и полный набор входов, новые/удалённые файлы и согласованность release.json с ZIP. `tests/pipeline.test.js` проверяет отказы; preflight отклоняет неизвестные/несовместимые флаги до тестов. Изменение исходников во время проверки делает отчёт неуспешным.
