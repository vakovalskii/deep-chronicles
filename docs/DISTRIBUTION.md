# Публикация клиента и сайт скачивания — следующий этап

Сейчас клиент собирается самостоятельно, подключается к основному серверу, а сборка проверяется через `native:verify`. Сайт скачивания, обновлятор и публикация релизов пока не реализованы. Этот документ сохраняет согласованное направление для следующего этапа.

## Предлагаемая структура на существующем домене

- `https://realms.neuraldeep.ru/download/` — страница игры: скриншоты, системные требования, версия, изменения, выбор платформы и кнопки скачивания.
- `/releases/<version>/…` — неизменяемые архивы клиента и контрольные суммы SHA-256.
- `/releases/version.json` — текущая версия и относительные ссылки на готовые платформы. Файл обновляется последним, когда архивы уже доступны.
- `/ws` продолжает обслуживать игру. Браузерную версию сохраняем до отдельного решения о её месте на сайте.

Для Windows раздаём EXE/ZIP, для macOS — архив приложения (при необходимости DMG), для Android — подготовленный APK. Выпуск на iPhone требует отдельного процесса подписи и распространения; готовность desktop не означает готовность iOS.

Перед публичным релизом macOS нужна выбранная стратегия подписи/нотаризации, Windows — подписи установщика, мобильным платформам — свои ключи и SDK. Эти учётные данные не попадают в git. Текущий локальный macOS export не заявляется как публично нотаризованный релиз.

## Реальный онлайн

Уже существующий сервер отдаёт `{ "t": "hi", "online": N }` сразу после подключения, без логина. Сайт может открыть `wss://realms.neuraldeep.ru/ws`, дождаться `hi`, показать N и закрыть соединение. Повторять, например, раз в 30–60 секунд; ограничивать тайм-аут и увеличивать интервал при ошибках. При недоступности показывать «нет связи», а не выдуманный нулевой онлайн.

Пуш `online` сейчас получает только авторизованный клиент: обычная страница не должна ожидать его после `hi`. Позже при необходимости можно добавить отдельный HTTP `/api/status` с кешированием и health-check, сохранив источником данных серверный подсчёт игроков.

## Воспроизводимый выпуск

1. Зафиксировать исходники и версию; `npm ci`.
2. Запустить `npm run native:verify -- --build=<platform>` на нужном сборочном окружении.
3. Проверить подписанный экспорт и старт на целевой ОС; сохранить отчёт, скриншоты, SHA-256 и привязку к commit.
4. Подготовить страницу, архивы, изменения и `version.json` локально для проверки.
5. Опубликовать конкретный проверенный набор файлов; не заменять старые архивы по тем же адресам. Сохранить предыдущую версию для отката.

Самопроверка новой версии в клиенте — отдельная небольшая функция: загрузить `version.json`, сравнить версию и открыть страницу скачивания. Начать можно с этого, затем добавить загрузку обновления. JSON не должен содержать команды для исполнения. Сайт и клиент используют HTTPS, секретные данные серверной БД на сайт не выгружаются.
