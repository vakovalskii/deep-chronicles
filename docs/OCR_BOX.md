# OCR-бокс: возврат в production

Хост из `TRELLIS_SSH` — production-сервер распознавания документов. Для моделей игры на нём временно запустили `trellis2-api` и остановили OCR. Просьбы пользователя «верни оср сервер обратно под оср пайп» и «оср бокс на прод» ранее ошибочно трактовались как OSS/open source. Этот документ исправляет память: они не разрешают публикацию игрового кода.

18.09.2026 при проверке обнаружено: TRELLIS занимал около 16 ГБ GPU, 28 задач генерации завершены, очередь пуста; все 7 OCR-контейнеров остановлены. После проверки принадлежности генератора (`/trellis2/work-l2`) остановлен только `trellis2-api`, запущены существующие контейнеры штатного OCR. Образы не пересобирались, Docker volumes и секреты не менялись, модель и код OCR не обновлялись. Игровой сервер работает на своём хосте; готовому клиенту TRELLIS не нужен.

## Восстановленное состояние

- MongoDB и MinIO — running/healthy.
- Paddle vLLM и worker — running/healthy.
- Обе реплики API — running/healthy, Traefik — running.
- `/healthz`, `/readyz`, `/api/v1/profile` через штатный балансировщик на 8090 возвращают HTTP 200.
- Модель: `PaddleOCR-VL-1.6-0.9B`, runtime `paddle-vllm`, профиль `standard-ocr`.
- TRELLIS — exited, restart policy `no`.
- Полный проверочный запрос через API: загрузка PNG → очередь → обработка → получение результата страницы. Задача `job_4ca59d4e29c5fa4bfe4924df` завершена за 10384 мс; текст `OCR PIPELINE RESTORED 73915` совпал полностью. Webhook для теста не задавался; пользовательские документы не использовались. Синтетическая задача удалится по штатному retention.

Свидетельства: `.native-run/ocr-restoration-smoke.log`, `.native-run/ocr-restoration-status.log`. Адрес SSH и ключи не входят в git.

## Воспроизведение

```sh
# Только статус контейнеров и штатного API:
node --env-file=.env tools/trellis/ocr-box.mjs --status

# Вернуть существующий OCR, сохранив контейнеры/volumes/конфигурацию:
node --env-file=.env tools/trellis/ocr-box.mjs --restore

# Одна синтетическая задача без webhook; проверяется точный результат OCR:
node --env-file=.env tools/trellis/ocr-box.mjs --smoke
```

Сценарий проверяет владельца Compose-контейнеров. Если TRELLIS работает, перед остановкой проверяет mount игры и отсутствие queued/running задач; при неопределённом состоянии отказывает. Запускает только остановленные OCR-контейнеры, ждёт готовности до 10 минут и печатает краткий статус. Повторное выполнение при здоровом OCR ничего не перезапускает. Чужие GPU-задачи и другие контейнеры не затрагиваются.

`--smoke` берёт уже установленный API-ключ из окружения API только внутри удалённого процесса и не печатает его. Тестовая картинка создаётся существующим Pillow в worker; используются `python3` и встроенный шрифт, установка пакетов не требуется.

**Не останавливать production OCR ради игровой графики.** Для следующих генераций нужен отдельный GPU или отдельно согласованное пользователем окно работ с обязательным возвратом OCR и проверкой через штатный API. Наличие SSH-доступа к этому хосту не делает его выделенным игровым GPU.
