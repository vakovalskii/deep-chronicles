# Переход на Unreal Engine 5

Дата: 18.09.2026. Решение пользователя принято; **реализация переноса ещё не началась**. UE Editor не установлен, `.uproject` и сборки UE отсутствуют. Сейчас выбираем другую машину разработки. Очистка текущего Mac остановлена по просьбе пользователя; файлов в ходе аудита не удаляли.

Текущая игра работает на Godot 4.7.2 с Node.js/WebSocket/SQLite. Сервер, аккаунты, персонажи, прогресс и протокол сохраняем. Godot остаётся доступным для сравнения и запуска до проверки замены. Браузерную игру не возобновляем: сайт служит для скачивания и статуса. Целевые платформы остаются Windows, macOS, Android и iOS; наличие проекта/настроек экспорта не считается проверкой платформы.

- Известный незакрытый отказ: последний touch headless прогон Godot — 177 проверок, 1 отказ уклонения от серверного удара. Проверить дистанцию, время замаха и соответствие выбранного моба событию. Не увеличивать допуски вслепую и не отключать проверку. Полный релиз этой итерации не выполнялся.
- Персональная выдача запрошенным двум персонажам уровня 25 и совместимого B-комплекта +16 уже выполнена на основном сервере с резервной копией; её не повторять при развёртывании клиента. Универсальный инструмент — `tools/admin/grant-gear.mjs`, dry-run по умолчанию.

- OCR-бокс работает на production OCR. Не использовать его GPU/диск для UE или генерации и не останавливать сервисы без отдельного указания.

- [ ] Планировать место для движка, SDK, исходников, импорта, shader/DDC-кэша и нескольких сборок. Ранее предложенные 100–150 ГБ свободного места — начальный рабочий запас, не фиксированный размер UE и не гарантия для большого мира. Точный набор компонентов/размер проверить в установщике.
- [ ] Установить движок через официальный Epic Launcher или официальный исходный код при наличии доступа. Вход в аккаунт делает пользователь; не извлекать сессии других приложений.

## 1. База проекта и серверная связь

Предлагаемая структура, **пока не создана**: `unreal/` для проекта, `tools/unreal/` для экспорта/импорта/сборки. Общие данные не переносить под Godot или UE: источниками остаются `server/` и `src/{data,stats,sim,progression,world-core,pvp,loot}.js`.

- [ ] Создать C++-проект, карту входа и игровую карту, управление/камеру, UI-слой; закрепить версии плагинов.
- [ ] Реализовать WebSocket/TLS адаптер существующего протокола, авторизацию и обработку `authok/you/snap/ev/fix`, heartbeat и reconnect. Документ: [протокол](gitmark/reference/protocol.md). Предлагаемый транспорт: [FWebSocketsModule](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/WebSockets/FWebSocketsModule).
- [ ] Сохранить запрет цикла входов при вытеснении второй сессией (`4001`), разделение токенов по endpoint, отсутствие паролей/чатов в сетевом журнале. Во время тестов не создавать аккаунты в production.
- [ ] Экспортировать каталог, высоты, препятствия, NPC и спавны из общих JS в формат для UE. Зафиксировать преобразование осей и единиц; сравнить контрольные координаты, размеры и высоты с сервером.
- [ ] Подключить предсказание/интерполяцию движения и обработку серверной коррекции; не считать на клиенте урон, XP/SP, дроп, покупки или экипировку.
- [ ] Приёмка: два клиента на отдельном локальном сервере видят друг друга и одного моба; вход, движение, бой, смерть, XP/SP и подбор меняют единственный серверный профиль. Существующий Godot продолжает понимать протокол.

## 3. Модели, мрачное окружение и бой

- [ ] Сделать воспроизводимый импорт существующих GLB/glTF, скелетов, анимаций, PBR, иконок и аудио с реестром источников/лицензий/хешей. Начать с героя, одного моба, оружия и стартового участка.
- [ ] Анимации не считать автоматически перенесёнными из моделей: часть клипов Godot подключает из общей библиотеки. Проверить скелеты, оси, bind pose, root motion/in-place, ретаргет и контакты стоп. Импорт скелетов/анимаций выполнять в редакторе/сборочном этапе; [runtime Interchange имеет ограничения](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-assets-using-interchange-in-unreal-engine).
- [ ] Сохранить albedo/normal/roughness, проверить соглашение normal map, цветовое пространство, mipmaps/LOD и коллизии; повторить аудит габаритов/хвата в UE.
- [ ] Довести один эталонный участок: строгая каменная архитектура, детализированные стены/пол, холодный рассеянный свет и тёплый огонь, выразительные силуэты героев и мобов. Затем расширять на города/карту. Референсы L2 задают направление; их текстуры/модели не извлекать в продукт.
- [ ] Улучшать бег/атаку/каст итерациями по записи реальной игры: стопы не скользят, оружие остаётся в руке, замах читается и совпадает с сервером, реакции/звук соответствуют подтверждённым событиям. Клиентские эффекты не откладывают серверный урон.
- [ ] Определить измеряемые бюджеты кадра, видимых акторов, памяти/VRAM и загрузки на выбранных ПК/телефонах. Проверить массовый бой и слабый профиль графики; Nanite/Lumen не делать обязательными для всех платформ.

## 4. Воспроизводимость, распространение и обновление

- [ ] Из чистого clone: установка закреплённых инструментов → экспорт общих данных → импорт → сборка → серверные и клиентские тесты → пакеты/хеши/манифест. Ручные правки только в редакторе не являются конвейером.
- [ ] Для UE добавить правила Git/LFS для исходных бинарных ассетов по выбранной схеме хранения; не переносить всю историю в LFS без отдельной необходимости. Исключить DerivedDataCache, Intermediate, Saved, Binaries, SDK и движок. Секреты/БД/токены остаются вне Git.
- [ ] CI Windows/macOS, запуск упакованного приложения с отдельным сервером, сценарии двух клиентов, чата/drag, пати/награды/дропа, смерти, TLS/reconnect и сохранения профиля. Отчёты, снимки и логи привязывать к commit/toolchain. Рендер и физические устройства проверять отдельно от headless.
- [ ] Добавить UE-пакеты в существующий сайт: версия, платформа, размер, SHA, реальные ссылки и онлайн сервера; проверить скачивание целиком. Windows — запускаемый EXE с нужными файлами в архиве; macOS — приложение. Мобильные каналы, подпись и SDK проверить отдельно.
- [ ] Реализовать [автообновление](AUTO_UPDATE.md): предложение новой версии → фоновая загрузка → явная кнопка закрытия/замены/перезапуска. Подписанный манифест, проверка пакета, версии в отдельных каталогах, внешний updater, сохранность настроек, откат. Наличие ZIP/release.json само по себе этим не является.
- [ ] Разделить сохранённую версию в Git и выпуск в production. Перед promotion пройти полный конвейер, резервировать серверную БД на сервере и обеспечить откат кода. Не загружать локальную БД вместо аккаунтов игроков.
- [ ] После успешного релиза открыть пользователю финальную сборку с основным сервером; не вытеснять его активную Windows-сессию автоматическим входом с другого устройства.
