# Архитектура

«Хроники Глубин» — MMORPG-песочница в духе классических корейских MMO (механика и названия свои).
Три части и один мост между ними:

```
  godot/           нативный клиент (Godot 4.7.2) — основной
     │  WebSocket JSON, порт 8790 (в проде nginx /ws)
  server/          авторитетный сервер (Node.js + ws), цикл 10 Гц
     │  импортирует
  src/*.js         общие правила: данные, статы, симуляция, мир
     │  запекает (tools/godot/export.mjs)
  godot/generated/ данные для клиента: мир, каталог, высоты, модели, UI_RULES
```

Плюс легаси: [браузерный клиент](docs/gitmark/services/web-client/README.md) на three.js в `src/main.js`.

## Правило

**Всё, что влияет на прогресс, считает сервер.** Клиент шлёт намерения и рисует ответ;
локально ничего игрового не хранится.

| На сервере | На клиенте |
|---|---|
| профиль, сумка, экипировка, заточка, монеты, опыт, уровень | отрисовка, частицы, подписи, звук интерфейса |
| мобы: спавн, ИИ, агро, урон, смерть, дроп, респавн | интерполяция мобов и игроков по снапшотам |
| весь бой: автоатака, умения, PvP, стражи, карма | шаг к цели, чтобы попасть в радиус |
| переходы в катакомбы, телепорты, возрождение | полоса каста, окна, перетаскивание в сумке |

Единственное исключение — **положение ведёт клиент**, иначе ходьба становится ватной.
Сервер проверяет скорость (`flatDist > speed*1.8*dt + 2`) и на рывок отвечает `fix`,
возвращая игрока назад. После серверного телепорта проверка глушится на 2 секунды (`warpUntil`).

## Почему общий код уцелел при переезде на Godot

Правила нельзя было переписать на GDScript, не потеряв отлаженный сервер и тесты.
Поэтому Godot их **не дублирует, а получает данными**: [`tools/godot/export.mjs`](tools/godot/export.mjs)
импортирует JS-модули в Node и запекает `godot/generated/`:

| артефакт | из чего | зачем клиенту |
|---|---|---|
| `world.json` | `src/world-core.js` | зоны, города, NPC, спавны, препятствия, расстановка моделей |
| `heights.bin` | `heightAt()` | сетка высот 501², шаг 4, начало −1000 |
| `catalog.json` | `src/data.js`, `src/stats.js`, `server/sim/player.js` | предметы, умения, классы + `UI_RULES` |
| `actors/*.glb`, `anims/` | `src/models.js`, `src/glb.js` | модели и запечённые клипы idle/walk/attack |
| `stats-fixtures.json` | `src/stats.js` | 48 профилей — ими `smoke.gd` сверяет клиентское зеркало правил |

Инвариант закреплён тестом: `src/world-core.js`, `src/sim.js` и `server/*` **никогда** не
импортируют `three` или `world.js` (`tests/unit.test.js:278-286`).

## Мир

Детерминированная расстановка: `buildProps(B)` в [`src/world-core.js`](src/world-core.js)
один раз строит мир и отдаёт геометрию через подключаемый эмиттер — сервер передаёт
`nullEmitter` и получает только данные. Карта 1600 м, два города (безопасные зоны),
три зоны с диапазонами уровней, склеп и **катакомбы за x ≥ 2200** — отдельная площадка с
лабиринтом на сеточном DFS с фиксированным зерном и полом y = 0.

## Тестовый контур

| прогон | что покрывает |
|---|---|
| `npm test` | `tests/unit.test.js` (правила, мир, экипировка, бой, ИИ) → `tests/server.test.js` (настоящий сервер, античит) → `tools/godot/test.mjs` (нативный smoke) |
| `npm run test:web` | то же + сборка Vite + Playwright-E2E браузерного клиента |
| `npm run native:verify` | воспроизводимая приёмка сборки, [runbook](docs/gitmark/ops/native-build.md) |

Добавил механику — добавь проверку в юнит-тесты или в нативный smoke.
