# Игровой сервер

> Актуализация 18.09.2026: браузерная игра закрыта. Клиент — только Godot; сайт `site/` — ZIP и онлайн. SP/ранги, автолут и крафт описаны в [PROGRESSION](docs/PROGRESSION.md), протоколе и AGENTS.md. Отдельный системный журнал, панель действий, масштаб миникарты и точная привязка к рельефу проверяются native smoke. Полный релиз: `native:verify -- --release`, затем `deploy -- --verified`.


Node.js + `ws`, один процесс, главный цикл **10 Гц**. Владеет всем, что влияет на прогресс:
профилем, сумкой, экипировкой, заточкой, боем, мобами, PvP и кармой. Клиент присылает
намерения и рисует ответ.

Единственное исключение — **положение ведёт клиент** (иначе ходьба становится ватной),
но сервер проверяет скорость и на рывок отвечает `fix`, возвращая игрока назад.

## Состав

| файл | за что отвечает |
|---|---|

## Константы главного цикла

`server/server.js:15-33`

| имя | значение | смысл |
|---|---|---|
| `TICK` | 100 мс | частота главного цикла (10 Гц) |
| `VIEW` | 220 м | радиус снапшота и видимости |
| `NEAR` | 60 м | радиус чата «рядом» |
| `LAG_M` | 4 м | допуск дистанции удара: клиент видит мир на ~250 мс в прошлом |
| `PORT` | 8790 (env `PORT`) | порт WebSocket |
| `DB` | `server/data/realms.db` (env `DB`) | файл SQLite |
| `AUTH_TRIES` | 12/мин на IP | лимит попыток входа; IP берётся из первого хопа `x-forwarded-for` |
| `DEV_CMD` | выкл. | `=1` включает отладочную команду `dev`; в проде её нет |

Порядок одного тика (`server/server.js:396-445`): `dt` (обрезан 0.5 с) → тик мобов
(`world.tick`, урон мобов по игрокам через колбэк) → `guardsTick` → по каждому игроку:
реген, снятие флага, дорезолв каста, автоатака → рассылка (`look`-диффы, новые виды мобов,
`snap`, `ev`, `you`). Сейв всех игроков — каждые 30 с, WS-`ping` — каждые 25 с, чтобы nginx
не рвал простаивающие соединения. Подбор сохраняется в SQLite немедленно; SIGTERM/SIGINT сохраняют активные профили перед выходом.

## Бой

- `applySkill` (`:230-264`) — ветвление по `sk.kind`: `dmg`, `heal`, `buff`, `aoe`.
  AoE задевает игроков только если они с флагом/красные либо это явная цель.
- `autoAttack` (`:267-287`) — интервал `1/aspd`; у мага автоатака идёт как магия `matk*0.6`;
  в городе атака запрещена.
- `damageMob` — опыт и право на добычу получает нанёсший **больше урона**. Опыт выдаётся сразу, монеты и вещи создаются на земле и зачисляются только после `pickup`. Защита аккаунта — 20 с, затем общий подбор; радиус 3 м; срок 5 минут (`src/loot.js`). Убийство моба смывает карму на `ceil(xp / karmaPerXp)`.
- `damagePlayer` / `damageActor` — уклонение, затем `calcDmg` по нужной школе защиты;
  PvP в городе запрещён полностью.

## PvP, карма и стражи

`server/server.js:289-358`, константы — [`src/pvp.js`](src/pvp.js).

- `status(a)`: `0` белый · `1` фиолетовый (активен флаг, 30 с) · `2` красный (карма > 0).
  Едет в снапшоте восьмым полем игрока.
- Удар по белому без собственного «красного» статуса вешает флаг на 30 с.
- Убийство засчитывается, только если убийца задел жертву за последние 10 с (`hitBy`).
  Убил с флагом/красного → `pvp++`; убил белого → `pk++`, карма `+karmaForPk(pk)`,
  общесерверный `announce` с названием зоны.
- Смерть PK роняет вещь: 50 % шанс, из них 35 % — надетая градовая вещь, иначе из сумки;
  подбирает убийца, о находке объявляют всем (`pkDrop`, `:329-350`).
- Стражи (8 на город, роль `guard`) бьют красных в радиусе 22 м на 22 % максимума HP,
  не чаще раза в 1300 мс.
- Раз в 60 с сервер объявляет, где находятся все PK онлайн.

## Профиль и сохранения

`server/sim/player.js`

- **`SAVE_VERSION = 3`**. Сейв другой версии или с неизвестным классом молча пересоздаётся
  (`loadChar`, `:28-42`). Всё загруженное зажимается: уровень, монеты, только существующие
  предметы, стек 1..9999, заточка 0..`MAX_ENCH`, HP/MP по посчитанным статам.
- Новичок (`newChar`) сразу **одет**: оружие по классу, тканевые доспех и поножи,
  150 монет, 5 зелий HP, свиток побега, дом — первый город.
- `skillError` (`:200-210`) — авторитетный шлагбаум умения: существование, жив ли, не кастует ли,
  свой ли класс, уровень, кулдаун, мана, город (в городе можно только лечение и баф).
- Реген: 0.6 %/с HP и 1.2 %/с MP, ×4 в городе, ×0.5 при перегрузе.
- `profileOf` шлёт профиль **целиком** — дельт нет, поэтому рассинхрона не бывает.

## Аккаунты

[`server/accounts.js`](server/accounts.js), `node:sqlite` в режиме WAL, две таблицы:
`accounts(key PK, name, salt, hash, created, save, saved)` (ключ — имя в нижнем регистре) и
`tokens(hash PK, key, created)`.

- Пароль: `scryptSync(pass, salt, 32)`, соль 16 байт, сверка через `timingSafeEqual`.
- Токен устройства: 24 случайных байта клиенту, в базе только **sha256**.
- Имя `^[\p{L}\p{N}_-]{3,16}$`, пароль 4–64, сейв ≤ 64 000 байт; при записи сейв штампуется
  каноническим именем — переименовать аккаунт подсунутым блобом нельзя.

## Подводные камни

- Идентификатор игрока в сети — **номер соединения**, он новый после каждого реконнекта.
  Снапшоты и `look` работают по нему, а личка ищет собеседника по ключу аккаунта
  (`server/server.js:367`) — это разные пространства имён.
- `PVP.minHitMs` и `PVP.atkCap` объявлены в `src/pvp.js`, но в сервере не используются.
- Команда `dev` — единственная причина существования `DEV_CMD`; на неё опираются оба
  тестовых набора, а в systemd-юните её нет.

## Тесты

`npm run test:server` → [`tests/server.test.js`](tests/server.test.js) поднимает настоящий
сервер на 8792 с временной базой и проверяет в том числе, что подделать профиль с клиента
нельзя, что покупка вдали от торговца и заточка без свитка отбиваются, что рывок через
полкарты ловится `fix`, а второй вход выкидывает первую сессию.
Добавил команду клиента — добавь туда проверку, что её нельзя подделать.

Серверные тесты подбора используют двух игроков: видимость одного ID, отказ чужому/далёкому, повтор, подмена награды, исчезновение у соседа и чтение SQLite до отключения владельца. Полная схема: [GROUND_LOOT](docs/GROUND_LOOT.md).
